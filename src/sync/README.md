# Синхронизация через Google Drive

Файлы: `auth.ts` (вход через Google Identity Services, token flow), `drive.ts` (клиент Drive REST v3),
`merge.ts` (трёхстороннее слияние, SPEC §7), `syncEngine.ts` (цикл синхронизации).

## Что настроить перед запуском

1. [Google Cloud Console](https://console.cloud.google.com/): создать проект (или взять существующий).
2. **APIs & Services → Library**: включить **Google Drive API** и **Google Calendar API**.
3. **OAuth consent screen**: тип *External*, режим публикации **Testing**; в **Test users** добавить
   свой Google-аккаунт. Скоупы: `drive.appdata`, `drive.file`, `calendar.app.created`.
   В режиме Testing Google при входе покажет «приложение не проверено» — для личного пользования это нормально.
4. **Credentials → Create credentials → OAuth client ID**, тип **Web application**.
   В **Authorized JavaScript origins** добавить адреса, откуда открывается приложение, например
   `http://localhost:5173` (dev) и `https://<user>.github.io` (хостинг). Redirect URI для token flow не нужен.
5. Передать client ID приложению одним из способов:
   - при сборке: `VITE_GOOGLE_CLIENT_ID=<id>.apps.googleusercontent.com` в `.env.local`;
   - или в настройках приложения на устройстве (`auth.setClientId`, хранится в localStorage).

Секрета клиента у Web-клиента в token flow нет, client ID не секретный.

## Ограничения

- **Запись в Drive не атомарна.** Drive v3 не поддерживает If-Match для содержимого файла. Перед записью
  синхронизатор перечитывает `version` и повторяет цикл, если файл изменился, но между проверкой и записью
  остаётся короткое окно. Если устройство A запишет файл в это окно, оно перетрёт только что записанную
  версию устройства B. Как правки B возвращаются:
  - B помнит свою запись в base-снимке, и в следующем цикле видит в Drive не правку, а откат: значение
    поля отличается от base, а его метка времени (`fieldUpdatedAt`, у контактов и settings — `updatedAt`)
    старше метки в base. Такое значение `merge` отбрасывает и оставляет правку B, которую B снова
    отправляет в Drive. Так же возвращаются перетёртые новые записи и удаления (tombstone);
  - A, получив после PATCH версию больше ожидаемой (прочитанная + 1), сразу запускает ещё один цикл.

  Правка B возвращается в Drive только следующим циклом самого B (через ~3 с после правки, раз в 60 с,
  при возврате на вкладку). Если B за это время закроют и не откроют, правка B останется только на B.
- **Метки времени берутся с часов устройства.** Правку на устройстве, чьи часы отстают больше чем на разницу
  между правками, `merge` может принять за откат. Слияние будет стабильным, но такая правка проиграет.
- Токен живёт только в памяти (~1 час). После перезагрузки страницы или истечения токена выполняется
  тихий запрос (`prompt: ''`). Если браузер его блокирует (сторонние cookie, блокировщик всплывающих окон),
  статус становится «нужен вход», и пользователь нажимает «Войти».
- Email аккаунта берётся из Drive `about.get`: скоуп `openid` не запрашивается.
