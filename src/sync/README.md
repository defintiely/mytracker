# Синхронизация через Google Drive (Google Apps Script)

Трекер не ходит в Google API напрямую. Между ним и Google стоит маленький скрипт Google Apps Script в
аккаунте самого пользователя, развёрнутый как веб-приложение. Google Cloud Console, OAuth Client ID,
тестировщики и «Publish app» не нужны.

Файлы:

| Файл | Что внутри |
|:---|:---|
| `scriptApi.ts` | Контракт трекер ↔ скрипт: запросы `ping`, `load`, `save`, `calendar`, коды ошибок |
| `scriptSource.ts` | `buildScriptSource(key)` — полный текст скрипта с вшитым ключом; календарная часть — `src/calendar/calendarGs.ts` |
| `scriptClient.ts` | Клиент на `fetch`, хранение подключения (`localStorage['wlt.script']`), ключ, ссылка подключения |
| `merge.ts` | Трёхстороннее слияние (SPEC §7) |
| `syncEngine.ts` | Цикл синхронизации и его запуски |
| `errors.ts` | `OfflineError`, `ScriptCallError` |

## Как подключить (делает пользователь, один раз)

Всё это показано пошагово в «Настройки → Google Drive через Apps Script».

1. Нажать «Скопировать код скрипта» и открыть https://script.google.com/create под нужным Google-аккаунтом.
2. Удалить всё в редакторе, вставить код, нажать «Сохранить».
3. «Развернуть» → «Новое развёртывание» → шестерёнка → «Веб-приложение». Выполнять от имени: **Я**.
   У кого есть доступ: **Все**. «Развернуть».
4. Разрешить доступ: «Предоставить доступ» → аккаунт → «Дополнительные настройки» → «Перейти на страницу …
   (небезопасно)» → «Разрешить». Предупреждение стандартное для любого личного скрипта.
5. Скопировать «URL веб-приложения» (`https://script.google.com/macros/s/…/exec`), вставить в трекер, «Подключить».
   Трекер делает `ping` и сохраняет подключение.

Второе устройство: на первом в настройках скопировать «Ссылку для телефона и других устройств»
(`…/exec#k=<ключ>`) и вставить её в то же поле на втором. Скрипт второй раз создавать не нужно.

## Что делает скрипт

- `ping` → `{ ok, protocol, email }`: версия протокола и email владельца.
- `load` → `{ ok, doc, rev }`: содержимое `tracker.json` и ревизия (`doc: null`, если файла нет).
- `save(doc, baseRev)` под `LockService.getScriptLock()` (ожидание до 20 с): если `baseRev` не равна текущей
  ревизии — `{ ok:false, code:'conflict', rev }` и ничего не пишется; иначе файл перезаписывается и ревизия
  растёт на 1. Ревизия хранится в свойствах скрипта (`PropertiesService`, ключ `rev`).
- `calendar` — ведение календаря (`handleCalendar_`, см. `src/calendar/calendarGs.ts`).
- Любой запрос без правильного ключа → `forbidden`; не JSON → `bad_request`; исключение → `internal` с текстом.

Транспорт: `POST` с телом-строкой JSON и `Content-Type: text/plain;charset=utf-8` — это «простой» запрос,
браузер не делает CORS-preflight. Ответ — JSON через `ContentService`.

## Где лежат данные

- `Мой диск/Трекер/tracker.json` — данные трекера. Папка и файл создаются при первой записи.
- `Мой диск/Трекер/Бэкапы/backup-YYYY-MM-DD.json` — при первой записи за день скрипт копирует туда
  предыдущую версию файла. Хранятся 30 последних, старые уходят в корзину Drive.
- Восстановить из бэкапа: скачать нужный `backup-….json` и загрузить его в трекер через «Экспорт и бэкап».

## Синхронизация

Цикл (`syncEngine.ts`): `load()` → `merge(base, local, remote ?? local)` → если результат отличается от
файла или файла нет → `save(result, rev)`. Ответ `conflict` значит, что между `load` и `save` записало другое
устройство, — цикл повторяется (до 5 раз). После успеха документ применяется локально, `base` = результат,
проигравшие значения — в журнал конфликтов, затем выполняются afterSync-хуки (календарь) с клиентом скрипта.

Запись атомарна: проверка ревизии и запись идут под одной блокировкой скрипта, поэтому одно устройство не
может перетереть запись другого. (В прежней версии с прямым Drive API такое окно было.)

Запуски: при старте, при возврате на вкладку, при появлении сети, раз в 60 с и через ~3 с после правки.
Состояния: `disabled` (нет подключения), `offline`, `syncing`, `synced`, `dirty`, `error` (с текстом:
неверный ключ, скрипт развёрнут не с доступом «Все», ошибка скрипта). При смене адреса скрипта base-снимок
сбрасывается, и данные устройства объединяются с новым файлом, а не удаляются.

## Как обновить скрипт

Когда трекер просит обновить скрипт (сменилась версия протокола):

1. «Настройки → Показать код скрипта ещё раз» → «Скопировать код скрипта» (ключ тот же).
2. На script.google.com открыть свой скрипт, заменить код, «Сохранить».
3. «Развернуть» → «Управление развёртываниями» → карандаш → «Версия: Новая версия» → «Развернуть».
   Ссылка `…/exec` не меняется, на устройствах ничего перенастраивать не нужно.

Если вместо этого создать **новое** развёртывание, у него будет новая ссылка — её придётся вставить на всех устройствах.

## Безопасность ключа

- Доступ «Все» нужен, чтобы трекер мог обращаться к скрипту без входа в Google. Защищает данные ключ:
  32 случайных символа, которые трекер генерирует и вшивает в код скрипта (`const KEY = '…'`). Без ключа
  скрипт отвечает `forbidden` и ничего не читает и не пишет.
- Ключ хранится в коде скрипта (виден только владельцу аккаунта) и в `localStorage` устройств.
  Ссылка подключения содержит ключ — её нельзя публиковать.
- После «Отключить» трекер запоминает ключ, чтобы к тому же скрипту можно было снова подключиться одной ссылкой `…/exec`.
- Ключ утёк: «Отключить» на всех устройствах → в инструкции «Создать новый ключ» → пройти шаги заново
  (новый код, новое развёртывание) → подключить остальные устройства новой ссылкой подключения. Старое
  развёртывание архивировать в «Развернуть → Управление развёртываниями».

## Ограничения

- Квоты Apps Script (https://developers.google.com/apps-script/guides/services/quotas): одно выполнение —
  до 6 минут, одновременно — до 30 выполнений на пользователя, плюс суточные лимиты на создание событий
  календаря и операции Drive. Синхронизация раз в минуту на 2–3 устройствах укладывается с запасом: `load` и
  `save` — доли секунды. Массовая первая выгрузка сотен событий в календарь может упереться в суточный
  лимит создания событий — тогда остаток доедет на следующий день.
- Запись ждёт блокировку до 20 с; если не дождалась — синхронизация покажет ошибку и повторит позже.
- Ответ скрипта идёт через редирект на `script.googleusercontent.com`; первый запрос после простоя может
  занимать 1–3 секунды (холодный старт скрипта).
- Если скрипт развёрнут с доступом «Только я», браузер получает страницу входа Google вместо JSON. При
  подключении трекер говорит об этом прямо; в фоне такая ошибка выглядит как «нет связи со скриптом».
- Метки времени для слияния берутся с часов устройств. Правку на устройстве, чьи часы сильно отстают,
  `merge` может принять за откат, и она проиграет.
