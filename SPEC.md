# Трекер работы — спецификация v0.2

Дата: 2026-11-09 · Статус: черновик, открытые вопросы в §13

## 1. Зачем

Трекер для «средней» работы: фрилансер или небольшой бизнес любой сферы (консультации, проекты, разработка, дизайн, ремонт, обучение…). Часто учёт ведётся в самодельной таблице `.ods`: по листу на месяц, за несколько лет. Такой файл живёт на одном компьютере, с телефона его не открыть и не поправить. Записи забиваются вручную, у разных листов разный набор колонок, а календарь ведётся отдельно.

Нужно приложение, которое:
- открывается и с телефона, и с компьютера, и работает без сети;
- показывает те же записи в двух видах: **таблица**, как сейчас, и **задачи/карточки** со статусами;
- ведёт деньги по каждой задаче: у клиента, у посредника, получено;
- синхронизируется через Google Drive пользователя (без своего сервера);
- выгружает данные в ODS (единственный табличный формат на старте);
- синхронизируется с Google Календарём;
- один раз импортирует всю историю из `.ods`.

## 2. Каким бывает исходный файл

**Структура.** Один лист на месяц. Названия листов разношёрстные: «июнь», «февраль 2023», «Июнь  2024» (двойной пробел); у первых листов год может быть не указан. Внизу листа две формулы: `=SUM(D1:D31)` (оборот за месяц) и `=D32*<коэффициент>` (грубая оценка чистого дохода после налогов). Бывают листы-заготовки на будущие месяцы со скопированной строкой-мусором и пустые листы.

**Строка.** Одна строка — это одно событие (примеры выдуманные):

| Вид | Пример | Сумма |
|:---|:---|:---|
| Задача с датой | «12.06 Кафе Ромашка · 15.00 · консультация · €300 · Анна 99000001» | есть |
| Работа без даты | «поддержка сайта €700», «доработка для Коли €100» | есть |
| Предоплата / сертификат | «Предоплата за 1.09 €100», «сертификат на 300» | есть, относится к другой дате |
| Корректировка | «комиссия за 5–7 сентября −€200», «встреча €0 — оплата вместе с проектом» | ±/0 |
| Личное | «врач 17.30», «репетиция», «отпуск» | нет |
| Заметка/чек-лист | строки под итогом листа: «звонки по одному», «подготовить договор»… | нет |

**Поля** (позиции колонок от листа к листу плавают):

| Поле | Как записано | Проблема |
|:---|:---|:---|
| Дата | в начале текста ячейки: «1.06», «05.12», «12-14», «19-20.09», «29.06?» | дата склеена с местом, бывают диапазоны и «?» |
| Место / название | «Кафе Ромашка», «Grand hotel», «Альфа» | склеено с датой |
| Время | «9.00 утра», «16.00-23.00», «вечер», «уточнить», число `19.3` | свободный текст |
| Категория | «консультация», «проект», «встреча», «поддержка» | свободный текст |
| Сумма | € (currency), иногда просто число | — |
| Контакт | телефон, ссылка FB, «инст», «телеграм», «ватсап», «смс» | канал и номер в одной строке |
| Источник / посредник | «с Петей», «от Гали», «от ребят», «агенство» | повторяется, но не нормализован |
| Оплата | «оплачено», «оплчано», «оплачено 50 процентов», «оплачено в феврале» | опечатки, частичная оплата |
| Способ оплаты | «нал», «револют», «счет», «на счету», «у Пети» | — |
| Инвойс | «инв», «инв 28», просто число | номер в разных колонках |
| Заметки | «6 часов», «сделать инвойс», ссылка Google Maps | — |
| Цвет фона | несколько цветов на части строк | тип задачи или пометка «важно»; размечено не везде |

**Вывод для модели данных.** Одна запись хранит дату (или диапазон, или «без даты»), время (или «уточнить»), тип задачи (из списка типов пользователя), категорию, деньги со статусом оплаты, контакт, источник, номер инвойса (только как текст) и чек-лист. Личные дела хранятся в том же списке, только с типом без денег.

## 3. Пользователи и устройства

- Основной пользователь — владелец трекера: фрилансер или владелец небольшого дела. Устройства: Android/iOS-телефон и Windows-компьютер.
- Пользователь один, Google-аккаунт один. Второй человек трекер не открывает: при необходимости ему дают доступ на чтение к календарю трекера штатным общим доступом Google Календаря (§10).
- Язык интерфейса — русский. Валюта — EUR, формат дат — `дд.мм`.

## 4. Архитектура (рекомендация)

**PWA, статический хостинг, без своего бэкенда. «Сервер» — Google Apps Script в аккаунте пользователя.**

```
 Телефон / ПК (браузер, «установить как приложение»)
 ┌────────────────────────────────────────────┐
 │ UI: Таблица | Задачи | Календарь | Итоги    │
 │ Хранилище: IndexedDB (работает офлайн)      │
 │ Очередь изменений → синхронизатор           │
 └───────────────┬────────────────────────────┘
                 │ POST JSON + ключ (fetch, без входа в Google)
                 ▼
  Google Apps Script — веб-приложение в аккаунте пользователя
  (выполняется от имени владельца, доступ «Все», без ключа ничего не отдаёт)
         │ DriveApp                 │ CalendarApp
         ▼                          ▼
  Мой диск/Трекер/tracker.json   Календарь «Трекер»
  Мой диск/Трекер/Бэкапы/        (отдельный, создаёт скрипт)
```

- **Фронтенд:** TypeScript, React (или Svelte), Vite. Табличный вид — TanStack Table или AG Grid Community с редактированием в ячейках. Офлайн обеспечивает service worker (Workbox).
- **Хостинг:** GitHub Pages или Cloudflare Pages. Данные на хостинг не попадают: всё лежит в браузере и в Drive пользователя.
- **Доступ к Google — через Apps Script, без OAuth в браузере.** Трекер генерирует текст скрипта с вшитым случайным ключом (32 символа). Пользователь один раз вставляет его на script.google.com и разворачивает как веб-приложение: «Выполнять от имени: Я», «У кого есть доступ: Все». При первом развёртывании Google спрашивает разрешение на Drive и Календарь для этого скрипта (экран «приложение не проверено» — стандартный для личных скриптов). Трекер хранит на устройстве только адрес `…/exec` и ключ.
  - Google Cloud Console, OAuth Client ID, test users и публикация приложения не нужны.
  - Протокол — `src/sync/scriptApi.ts`: `ping`, `load`, `save`, `calendar`. Запросы — `POST` с телом-строкой JSON и `Content-Type: text/plain` (без CORS-preflight); запрос без верного ключа получает `forbidden`.
  - Второе устройство подключается «ссылкой подключения» `…/exec#k=<ключ>`, скопированной на первом.
  - Обновление скрипта: новый код → «Управление развёртываниями» → новая версия; адрес не меняется.
- **Почему не Google Sheets как основная база:** таблица, которую правят руками, ломает схему (сдвинутые колонки, опечатки), а слить правки двух устройств построчно в Sheets трудно. Поэтому таблицы — только выгрузка в ODS (§8).

Альтернатива: если нужен доступ без браузера и с уведомлениями, можно обернуть ту же PWA в Capacitor. В v1 это не входит.

## 5. Модель данных

```ts
type Entry = {
  id: string;               // uuid
  type: string;             // id типа задачи из Settings.taskTypes; задаёт цвет записи везде (таблица, карточки, календарь)
  kind: 'job' | 'work' | 'payment' | 'event' | 'note';  // служебное, в интерфейсе не показывается и не выбирается:
  //   ставится само при сохранении — есть дата → job (тип с деньгами) / event (без денег); нет даты → work (есть сумма) / note;
  //   payment (предоплата, сертификат, комиссия из импорта) сохраняется как есть
  //   job      — задача с датой («Задача»)
  //   work     — работа без даты, засчитывается в месяц учёта («Работа без даты»)
  //   payment  — предоплата, сертификат, комиссия, корректировка («Оплата»)
  //   event    — дело с датой без денег («Дело»)
  //   note     — заметка/чек-лист без даты («Заметка»)
  title: string;            // «Проект сайта для Альфы»
  date?: string;            // ISO 'YYYY-MM-DD'; нет — «без даты»
  dateEnd?: string;         // для «19-20.09», «13.10-14.10»
  dateTentative: boolean;   // «29.06?», «уточнить»
  timeStart?: string;       // 'HH:mm'
  timeEnd?: string;
  timeNote?: string;        // «вечер», «уточнить» — если не распознано
  allDay: boolean;
  location?: string;        // «Grand hotel»
  mapUrl?: string;
  category?: string;        // из Settings.categories: консультация, проект, встреча, поддержка…
  amount?: number;          // EUR, может быть 0 или < 0
  currency: 'EUR';
  money: MoneyPart[];       // где сейчас деньги по записи (см. ниже); сумма частей = amount
  invoiceNo?: string;       // «28» — просто текст для справки; инвойсы ведутся в отдельном приложении
  accountingMonth?: string; // 'YYYY-MM' — в какой месяц засчитать (работа без даты, предоплаты, «оплачено в феврале»)
  relatedEntryId?: string;  // предоплата → задача
  contactId?: string;
  sourceId?: string;        // партнёр / откуда заказ
  status: 'lead' | 'booked' | 'shot' | 'editing' | 'delivered' | 'done' | 'cancelled';
  //   подписи: Заявка, Запланировано, Сделано, В работе, Сдано, Закрыто, Отменено (id в данных не меняются)
  checklist: { id: string; text: string; done: boolean }[];
  notes?: string;
  calendarEventId?: string;
  createdAt: string; updatedAt: string; deleted?: boolean;  // tombstone для синхронизации
  origin?: { sheet: string; row: number; raw: string };     // откуда импортировано
};

// Деньги по записи могут лежать в разных местах и переходить между ними.
// «оплачено 50 процентов» = две части: 50% у владельца, 50% у клиента.
type MoneyPart = {
  amount: number;
  where: 'client'        // клиент ещё не заплатил
       | 'intermediary'  // заплачено посреднику/партнёру (Петя, агентство), ему ещё передать владельцу
       | 'owner';        // деньги у владельца
  holderId?: string;     // кто именно посредник (Source)
  method?: 'cash' | 'revolut' | 'bank' | string;  // нал / револют / счёт
  at?: string;           // когда перешли в это состояние
};
// История переходов (клиент → посредник → владелец) пишется в журнал записи.
// Производный статус оплаты для фильтров и значка: не оплачено / частично / у посредника / получено / без денег.

type Contact = { id; name; phones: string[]; channels: { kind: 'whatsapp'|'telegram'|'instagram'|'facebook'|'sms'|'email'; value: string }[]; notes?; updatedAt };
type Source  = { id; name; commissionPct?: number; updatedAt };  // Петя, Галя, «ребята», агентство
type Settings = {
  netFactor: number /* 0.67 */;
  categories: string[];          // по умолчанию: консультация, проект, встреча, поддержка, разработка, дизайн, обучение, прочее
  taskTypes: TaskTypeDef[];
  defaultTypeId?: string;        // тип по умолчанию: новые записи и записи с суммой при быстром вводе/импорте
  defaultNoMoneyTypeId?: string; // тип для дел без денег: записи без суммы и без признаков работы
  calendar: { calendarName: string /* «Трекер» */; ... };
  ...
};

// Тип задачи. Все типы равноправны: любой можно переименовать, перекрасить, переключить «с деньгами»
// и удалить — нельзя удалить только последний оставшийся. Удалённый тип помечается tombstone-ом
// deleted: true (чтобы синхронизация его не вернула), записи перед этим переводятся в другой тип.
type TaskTypeDef = { id: string; name: string; color: string; money: boolean; deleted?: boolean };
```

**Типы по умолчанию.** Новый документ получает три обычных типа: «Основная работа» (`main`, с деньгами), «Совместная работа» (`joint`, с деньгами), «Личное» (`personal`, без денег). Это обычные элементы списка — id сохранены только для того, чтобы записи старых документов не потеряли тип. Никакой код не опирается на эти id: «с деньгами» — всегда флаг `money` типа.

**Тип по умолчанию** — `defaultTypeId`; если не задан или тип удалён — первый живой тип с деньгами, иначе первый живой. **Тип для дел без денег** — `defaultNoMoneyTypeId`; если не задан или удалён — первый живой тип без денег, иначе тип по умолчанию. Оба выбираются в настройках типов.

У типов без денег (`money: false`) поля денег скрыты, такие записи не входят в оборот, а режим календаря для личных дел («Занято» / не выгружать) применяется ко всем им. Запись неизвестного типа (тип удалён на другом устройстве и т.п.) показывается серым и считается «с деньгами».

**Миграция старых документов** (при загрузке из IndexedDB, из Drive и из бэкапа; идемпотентно): нет `taskTypes` — три типа по умолчанию (цвета из прежнего `typeColors`); старый флаг `builtin` у типов стирается, типы становятся обычными (имена, цвета и `money` — как были сохранены). У записей вид `shoot` переименовывается в `job`, поля `media` и `withEditing` (и их метки в `fieldUpdatedAt`) стираются. Имя календаря пользователя не меняется — «Трекер» подставляется только как значение по умолчанию.

**Цвета типов** (по умолчанию, меняются в настройках): основная работа — зелёный, совместная — голубой, личное — жёлтый; у новых типов — свой цвет. Цвет — главный визуальный признак записи: фон строки в таблице, полоса на карточке, цвет события в календаре, фон строки в выгрузке `.ods`. Статус показывается значком, а не цветом.

## 6. Экраны

### 6.1 Таблица (основной вид на ПК)
- Колонки: Тип · Дата · Время · Название · Место · Категория · Сумма · Где деньги · Способ · № инвойса · Контакт · Источник · Статус · Заметки. Набор и порядок колонок пользователь настраивает; строка окрашена цветом типа.
- Ячейки редактируются по месту. Tab/Enter переходят по ячейкам, вставка из буфера работает многострочно, есть автодополнение из справочников (места, контакты, источники, категории).
- Группировка по месяцам: заголовок месяца и строка итога (оборот, «чистыми ≈» = оборот × `netFactor`, получено / у посредников / у клиентов). `netFactor` — одна константа в настройках (0.67), это грубая оценка после налогов, а не бухгалтерия. Это замена листов и двух формул.
- Фильтры: период, тип задачи (все типы из настроек), статус оплаты, источник. В итогах месяца оборот разбит по типам с деньгами. Поиск по всему тексту.
- Записи без даты (работа без даты) показываются в своём месяце (`accountingMonth`) отдельной группой.
- На телефоне таблица сворачивается в компактный список строк с горизонтальной прокруткой, редактирование открывается в карточке.

### 6.2 Задачи (основной вид на телефоне)
- **Канбан** по `status`: Заявка → Запланировано → Сделано → В работе → Сдано → Закрыто. Карточку можно перетаскивать между колонками. Дела без денег показываются по галке.
- **Список «Сегодня / Неделя / Без даты / Просрочено»**. Под «просрочено» попадают: дата задачи прошла, а статус ещё «Запланировано»; сдано, но деньги ещё у клиента; деньги у посредника дольше N дней.
- **Экран «Деньги»:** сколько и за какие записи сейчас у клиентов и у каждого посредника. Перевод части денег «посредник → владелец» делается одним действием, можно сразу для нескольких записей («Петя передал за сентябрь»).
- Карточка: заголовок, тип, вид, категория, дата и время, место (по тапу открывается в картах), контакт (по тапу — звонок, WhatsApp или Telegram), сумма и оплата, чек-лист, заметки.
- Быстрое добавление одной строкой: «12.12 встреча 11-12 200 от Пети» разбирается в поля тем же парсером, что и импорт (§9).

### 6.3 Календарь
- Месяц и неделя: задачи, личные дела и предварительные записи (`dateTentative`, отрисованы пунктиром).
- Пересечения по времени подсвечиваются (защита от двойного бронирования).

### 6.4 Итоги
- По месяцам и годам: оборот (с колонкой на каждый тип с деньгами), «чистыми ≈», число задач, средний чек, разбивка по типам задач, категориям и источникам, сколько денег у клиентов и у посредников.
- Сравнение с тем же месяцем прошлого года.

### 6.5 Настройки — типы задач и категории
- Блок «Типы задач»: у каждого типа образец цвета (выбор цвета), название (правка по месту), «с деньгами» и «Удалить» — одинаково у всех типов. У последнего оставшегося типа «Удалить» недоступно, рядом подсказка.
- Выбор «Тип по умолчанию» и «Тип для дел без денег» (§5).
- «+ Добавить тип»: название, цвет, «с деньгами» (по умолчанию да).
- Удаление типа: если есть записи этого типа — диалог «N записей этого типа → перевести в: [тип]», записи переводятся, тип помечается удалённым; если записей нет — подтверждение и удаление.
- Все списки выбора типа (таблица, карточка, фильтры, мастер импорта, сопоставление цвет → тип) берут типы отсюда.
- Блок «Категории»: список категорий пользователя; парсер определяет категорию по совпадению с этим списком.

## 7. Синхронизация через Google Drive

- Канонические данные лежат в одном файле `tracker.json` в папке «Трекер» в корне Drive пользователя: `{ schemaVersion, entries[], contacts[], sources[], settings }`. Объём небольшой: около 1000 записей за 5 лет дают ~0.5–1 МБ. Читает и пишет файл только скрипт (§4).
- У файла есть ревизия — целое число в свойствах скрипта: растёт на 1 при каждой записи, 0 — файла ещё не было.
- Локально данные хранятся в IndexedDB, каждое изменение пишется в очередь.
- Цикл синхронизации запускается при старте, при возврате на вкладку, раз в 60 с при наличии сети и через ~3 с после правки:
  1. `load` — получить `tracker.json` и его ревизию; документ приводится к текущей схеме (миграция из §5);
  2. слить: по каждой записи побеждает больший `updatedAt`; удаления хранятся как tombstone 90 дней;
  3. если обе стороны меняли одну запись после последней синхронизации, сливать по полям: разные поля объединяются, одно и то же поле решается по последней правке, а проигравшее значение уходит в журнал конфликтов (его видно в настройках);
  4. если результат отличается от файла (или файла нет) — `save(результат, ревизия из шага 1)`. Скрипт берёт блокировку (`LockService`), сверяет ревизию и пишет файл только если она не изменилась; иначе отвечает `conflict`, и цикл повторяется (до 5 раз). Проверка и запись идут под одной блокировкой, поэтому запись атомарна: одно устройство не может перетереть запись другого.
- Резервные копии делает скрипт: при первой записи за день копирует текущий файл в «Трекер/Бэкапы/backup-YYYY-MM-DD.json» и хранит последние 30.
- Индикатор состояния: «только на устройстве (не подключено) / синхронизировано / есть несохранённые правки / нет сети / ошибка» (ошибка с текстом: неверный ключ, скрипт развёрнут не с доступом «Все» и т.п.). Без подключения в шапке — кнопка «Подключить Google Drive», ведущая в настройки.

## 8. Экспорт

Табличный формат пока один — **ODS** (решено 2026-11-09). xlsx, csv, ics и Google Sheet-зеркало отложены.

- **ods**: по листу на месяц в привычной раскладке (дата, время, название, место, категория, сумма, где деньги, способ, № инвойса, контакт, источник, статус, заметки; фон строки — цвет типа) с формулами итога и `×netFactor`, плюс сводный лист «Итоги» (оборот, колонка на каждый тип с деньгами, чистыми, получено, у посредников, у клиентов, задач). Файл собирается в браузере собственным генератором (zip + `content.xml`/`styles.xml`): SheetJS Community не пишет и не читает цвета ячеек.
- Можно выгрузить весь трекер или выбранный период/фильтр.
- **json**: полный бэкап и восстановление из него (служебный формат, не для таблиц).
- Инвойсы трекер не формирует: для них отдельное приложение.

## 9. Импорт из `.ods`

Разовый перенос истории делает мастер в приложении. ODS читается в браузере собственным парсером (zip + `content.xml`), чтобы видеть цвета фона ячеек; данные никуда не загружаются.

1. **Месяц и год** берутся из названия листа. Листы без года получают год по порядку от ближайшего листа с годом. Пустые листы и строки пропускаются.
2. **Итоговые строки** (с формулами `SUM` и `*<коэффициент>`) не импортируются, а используются для сверки: сумма импортированных записей месяца должна совпасть с `SUM` листа. Расхождения выводятся в отчёт. Сверка — главный критерий правильного импорта.
3. **Парсер строки** (он же используется для быстрого ввода):
   - дата в начале текста: `д.мм`, `дд.мм`, `д-д.мм`, `дд.мм-дд.мм`, хвост `?` → `dateTentative`; дата из другого месяца остаётся как есть, с пометкой (например, «06.06 steam» на листе мая);
   - время: `HH.mm`, `HH.mm - HH.mm`, `HH.mm-HH.mm`, несколько интервалов через запятую, число `19.3` → 19:30; слова «утро/день/вечер/уточнить» уходят в `timeNote`;
   - сумма — ячейка типа currency или float в колонке суммы;
   - оплата: регулярка `опл[ач]+ен` (покрывает опечатки «оплчано», «оплчаено») → часть `owner`; «50 процент» → две части `owner` + `client`; «оплачено в <месяц>» → `accountingMonth`; ни оплаты, ни посредника → `client`;
   - инвойс: `инв\s*(\d+)` или голое число в колонке инвойса;
   - способ: нал / револют / сч[её]т → `method`; «у Пети», «на счету у Пети» → часть `intermediary` с `holderId` = Петя. Для старых записей (оплата давно прошла) мастер предлагает массово перевести такие части в `owner`;
   - источник: «с Петей», «от Пети», «от Гали», «от ребят», «агенство» → справочник `Source` (`sourceId`); тип записи источник не меняет;
   - контакт: телефоны (`\+?\d{8,12}`), ссылки facebook/instagram, слова ватсап/whatsapp/телеграм/инст/смс → `Contact` (дубликаты сливаются по телефону);
   - категория: по совпадению с категориями из настроек (по основе слова: «консультации» → «консультация»);
   - **признак денег**: парсер не выбирает тип, он отдаёт только признак «с деньгами»: есть сумма или признаки работы (оплата, инвойс, предоплата, слова «заказ/клиент/проект/договор…», совпадение с категорией) → да; иначе → нет (дело без денег: `event` с датой, `note` без даты);
   - **тип задачи**: если у строки есть цвет фона и он сопоставлен с типом — по цвету (флаг `money` этого типа решает, заводить ли деньги). Иначе — по признаку денег: «строки с суммой → тип» (по умолчанию тип по умолчанию) и «строки без суммы → тип» (по умолчанию тип для дел без денег). Оба выбора — на шаге «Типы» мастера, рядом с таблицей «цвет → тип» (любой тип или пометка «важно»; у каждого цвета — примеры строк и сколько из них с деньгами);
   - строки после итога листа → `note` / чек-лист;
   - строка без даты с суммой → `work` с `accountingMonth` листа;
   - «предоплата», «сертификат», «комиссия», отрицательная сумма → `payment`;
   - статус: прошедшая дата + деньги у владельца → `done`; прошедшая, деньги ещё не у владельца → `delivered`; будущая → `booked`.
4. **Экран проверки:** таблица «как было (сырой текст) → как распознано», неуверенные поля подсвечены, правка по месту, массовые действия («всё это — от Пети»). В каждой записи сохраняется `origin`.
5. **Будущие листы-заготовки** (с одной и той же скопированной строкой) определяются как дубликаты и по умолчанию не импортируются.
6. Повторный импорт того же файла не создаёт дублей: ключ — `sheet + row + raw`.

## 10. Синхронизация с Google Календарём

- Приложение создаёт отдельный календарь (по умолчанию «Трекер», имя меняется в настройках) и не трогает основной календарь. Этим календарем можно поделиться на чтение с другим человеком через штатный общий доступ Google Календаря — трекер для этого ничего не делает.
- Поскольку календарь могут видеть другие люди, суммы, источник и раздел «Деньги» в описание события **по умолчанию не пишутся**. Включается отдельной галкой в настройках. Дела без денег выгружаются по выбору: «как есть», «как „Занято“ без подробностей» или «не выгружать».
- **Из приложения в календарь** (основное направление): каждая запись с датой вида `job` или `event` становится событием.
  - Заголовок: название записи (без значков); без названия — категория, иначе «Задача» / «Дело»; предварительные — с префиксом `?`, отменённые (режим «пометить») — «Отменено: ».
  - Время — из `timeStart/timeEnd`; если времени нет — событие на весь день.
  - Место — `location`.
  - Описание: категория, контакт (кликабельный телефон), заметки; сумма и источник — только если включены в настройках.
  - Цвет события — цвет типа задачи (ближайший из палитры Google Календаря, `colorId`).
  - В `extendedProperties.private.entryId` хранится id записи для обратной связи.
- **Из календаря в приложение** (ограниченно): если в календаре трекера у события, созданного приложением, изменили дату или время, приложение подтягивает это в запись. Новые события, созданные прямо в календаре трекера, приложение предлагает импортировать как записи (тип по умолчанию, вид «Задача») — с подтверждением, без молчаливого создания.
- Отменённая запись удаляет событие или помечает его «Отменено» (выбирается в настройках).
- Напоминания: по умолчанию за 1 день и за 2 часа, настраиваются.
- Выгрузка `.ics` отложена: синхронизация идёт через Apps Script (CalendarApp).

## 11. Нефункциональные требования

- Офлайн: всё, кроме синхронизации, работает без сети. Правки, сделанные офлайн, уходят при появлении связи.
- Скорость: таблица с 2000 строк прокручивается плавно (виртуализация); холодный старт PWA на телефоне — до 2 с.
- Данные хранятся только в браузере и в Drive пользователя. Токенов Google в браузере нет: на устройстве лежат только адрес веб-приложения и ключ скрипта (localStorage). Ключ — 32 случайных символа; ссылку подключения с ключом не публикуют.
- Квоты Apps Script (время одного выполнения до 6 минут, суточные лимиты операций Drive и Календаря) при синхронизации раз в минуту с 2–3 устройств не достигаются.
- Доступность: таблица управляется с клавиатуры, крупные цели касания в мобильном виде, тёмная тема.
- Тесты: юнит-тесты парсера, тест импорта на своём файле (путь в `TRACKER_ODS`, файл в репозиторий не кладётся; проверяются только инварианты — сверка с `SUM`, согласованность денег), тесты слияния синхронизации (два устройства, конфликт поля, tombstone), тесты интерфейса.

## 13. Открытые вопросы

Решено (2026-11-09):
- `×0.67` — грубая оценка чистого дохода после налогов, одна константа `netFactor`.
- Деньги по записи могут быть у клиента, у посредника или у владельца, частями и с переходами → модель `MoneyPart` (§5) и экран «Деньги».
- Пользователь один. Второму человеку при необходимости открывается только календарь трекера через общий доступ Google.
- Календарь — отдельный, по умолчанию «Трекер».
- Типы задач — список пользователя, все типы равноправны (§5, §6.5); встроенных типов нет.
- Трекер универсальный: без специфики какой-либо профессии; категории — список пользователя.
- Инвойсы пока не делаем, для них отдельное приложение; в трекере только номер как текст.
- Мест для денег три: клиент, посредник, владелец. Список расширяемый, но других пока нет.

Открыто:
- Цвета исходного файла сопоставляются с типами в мастере импорта; цвет может означать и не тип, а пометку «важно» (идёт в заметки).
- Экспорт и импорт таблиц — только ODS.
